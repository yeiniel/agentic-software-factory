# Consolidate your memory

You remember in two places, and both are yours to edit:

- `~/.pi/agent/AGENTS.md`: what always applies. It is shown to you at the start
  of every turn, so it must stay short (the budget is in the request).
- `~/.pi/agent/skills/NAME/SKILL.md`: how to do something in a situation. Only
  its name and description are shown at the start of a turn, so the description
  must say when to use it; the steps are read when the situation comes up.

Do this, in order:

1. Read `~/.pi/agent/AGENTS.md` and list `~/.pi/agent/skills`.
2. Ask what the work showed. What happened counts: a command and what it
   printed, a bounce, a check's verdict, someone with authority saying how
   things are done. What you or others said happened, with nothing to show
   for it, is a claim: do not keep it as a fact.
3. For each thing worth keeping, choose where it goes:
   - It always applies, and fits in a line (a rule, and why in a few words):
     a line in `AGENTS.md`.
   - It is how to do something in a situation: a skill. Give it a `name` (lower
     case, digits, hyphens), a `description` that says what it is for and when to
     use it, and the steps.
   - Neither: do not keep it. An event, small talk or a one-off fact is not
     worth remembering.
4. Merge before you add. If it is about something you already have, edit that
   entry. If it replaces something, replace it: never keep both. Delete what is
   no longer true or no longer needed.
5. Keep `AGENTS.md` within its budget. If it is over, merge, or move a
   procedure into a skill, or delete the least useful line.
6. If the work showed nothing worth keeping, change nothing.

Finish with one line: what you added, merged or deleted, or that you changed
nothing. Do not write about consolidating in your memory.
